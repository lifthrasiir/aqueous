# `--convert`: 다른 아카이브를 Aqueous 아카이브로, Aqueous 아카이브를 다른 설정으로

구현은 `crates/aqr/src/convert.rs`(모듈 문서가 동작을 적는다)와 aqr-archive의 `rewrite.rs`(`rewrite_as`,
`rewrite_layered`, `rewrite_payload`, `History`, `Layers`)다. 이 문서는 그 결정의 이유와 정하지 않은 것을
적는다. 끝낸 일의 경과는 git 이력에 있다.

## 1. 범위

`aqr --convert INPUT... [-o OUTPUT]`는 아카이브 하나를 읽어 같은 트리를 담은 Aqueous 아카이브 하나를 쓴다.

1. **다른 형식에서**(ZIP, 7z, RAR, ALZ, EGG, tar와 압축기, 단일 파일 스트림: `aqr -d`가 읽는 것). `aqr -d`
   뒤 `aqr -c`와 같은 트리지만 디스크를 거치지 않으므로 파일 시스템이 담지 못하는 것(대소문자 충돌, 다른
   OS의 메타데이터, 특수 파일)도 잃지 않는다.
2. **이미 있는 Aqueous 아카이브의 설정 바꾸기**: 파일 맨 앞에서 시작하는 `.aqr`을 재압축 없이 `-P`, `-A`를
   걸거나 벗기거나 바꿔 다시 쓴다. 덧붙이기와 편집은 둘을 거절하므로(`append.rs`, `edit.rs`) 암호를 벗겨
   덧붙이고 다시 거는 길이기도 하다. 손상된 아카이브를 고쳐 쓰는 일(4.4절)과 journal 되돌리기
   (`--keep-until`, `append-design.md`)도 여기서 한다.

하지 않는 것:

- **Aqueous에서 다른 형식으로**: `aqr -c --format FORMAT`(aqr-pack)이 한다.
- **원본 그대로를 한 파일로**: `aqr -c foo.zip`이 한다(항목은 `foo.zip` 하나). `--convert`는 원본의 항목을
  트리의 항목으로 만든다. 원본을 바이트까지 되살릴 수 있게 함께 남기는 것(예약 경로 아래에 두고 다중 출력으로
  내용을 공유)은 구현하지 않기로 했다. 서명된 JAR/APK 등은 `aqr -c`로 담는다. 걸리는 점: 원본이 목록과 `-d`에
  함께 보인다.
- **SFX에서 독립된 `.aqr`로**(4.6절): 거절한다.

## 2. 명령줄

- 입력 하나에 아카이브 하나, `-o`는 입력이 하나일 때만. 형식은 `-d`처럼 이름과 매직으로 고르고, Aqueous
  아카이브(암호화된 것도)는 용례 2, 나머지는 용례 1이다. 앞에 다른 바이트가 있는 Aqueous 아카이브(SFX)는
  거절한다.
- 용례 1의 기본 출력은 형식을 알아보는 접미사를 뗀 이름에 `.aqr`(`foo.tar.gz` → `foo.aqr`)이다. 입력은
  남기고, 출력은 다 쓰고 검증한 뒤 제자리에 놓는다.
- 받는 옵션: 쓰는 쪽은 `-c`의 압축 옵션(용례 2는 4.1절), 읽는 쪽은 `--encoding`과 입력의 암호(4.3절).
  `--ipc`는 `mode`가 `convert`/`convert-new`다(`man/aqripc.7`).
- `--convert` 바깥의 `--no-passphrase`, `--no-archival`은 기본값이므로 아무 일도 하지 않는다(`-P`, `-A`와
  함께면 오류).

## 3. 용례 1: 다른 형식에서

aqr-unpack이 내용을 풀리는 대로 밀어 주고(push) aqr-compress는 트리 전체로 계획을 세워 내용을 당겨 간다
(pull). 다리는 전부 푼 다음 압축하는 것이다: 내용은 출력 옆의 spill에(입력이나 출력이 암호화되면 메모리에만)
두었다가 배치가 당겨 간다. 목록이 앞에 있는 형식과 tar 모두 이 길이다(tar는 끝까지 읽어야 목록을 알고,
`.tar.gz` 같은 것은 두 번 풀지 않으려고 전부 받아 둔다. 순방향 인코더, `docs/streaming-encoder-design.md`가
생기면 사라질 비용이다). 풀기와 압축을 겹치는 일은 하지 않았다.

### 3.1 메타데이터와 빠진 항목

- 트리는 `-d`가 만드는 것과 같다. ZIP의 대응은 spec "Converting from ZIP"이 정한다. 7z, RAR, ALZ/EGG,
  tar(pax, 확장 속성)는 spec에 같은 수준의 절이 없다. 변환이 대응을 아카이브에 영구히 남기므로 형식마다
  절을 쓴다 [남음].
- 주석: ZIP의 것(항목의 `comment`, Info-ZIP의 유니코드 필드, 아카이브의 EOCD 주석)을 옮긴다. RAR의 주석과
  Xceed의 0x554e는 아직이다 [남음].
- 볼륨 레이블: GNU tar의 형식 `V` 헤더를 `archive-label`(spec "Labels from tar", `-t`의 `Label:`, JSON의
  `label`, `-I`)로 담는다.
- `-d`는 빠진 항목(바깥으로 나가는 경로, 암호 없는 암호화 항목, 모르는 방식)을 알리고 끝에서 실패한다.
  `--convert`는 원본을 빠짐없이 옮겨야 하므로 하나라도 빠지면 출력 없이 실패한다. `-f` 같은 것으로 받아
  줄지는 열린 문제다.
- 링크는 빠진 항목이 아니다. 바깥을 가리키는 링크도 트리에 담고 막는 것은 풀 때의 일이다(`--links`).

### 3.2 재압축할 것인가

원본 항목의 압축된 바이트를 **몸**, 푼 데이터를 **내용**이라 한다. 고를 수 있는 것은 둘이다.

- **A. 다시 압축**: 내용을 보통 파일처럼 압축하고 몸은 버린다. 내용의 재압축기, 중복 제거, 배치 계획이 다
  붙는다. 비용은 압축 한 번이고 풀 때는 aqr의 속도다.
- **B. 몸을 그대로(carry)**: 몸을 slice로 두고 항목을 `Apply(디코더 모듈, 몸)`으로 만든다(`inflated.rs`의
  일반화: ZIP과 함께 묶인 파일 중 내용이 ZIP 속 DEFLATE 스트림과 같은 것을 `flate-inflate`로 만든다).
  변환 비용은 몸마다 한 번 푸는 것(CRC 확인)뿐이고 크기는 원본과 거의 같다. 약점: aqr가 잘하는 것이 하나도
  붙지 않는다(내용이 같은 두 항목도 따로 담긴다), 풀 때의 속도가 원래 코덱에 묶인다(모르는 모듈은 Wasm),
  모듈 바이트를 아카이브마다 싣는다. 몸을 다시 만드는 "무손실 재압축"은 변환된 항목이 내용이므로 쓸 데가
  없고 원본을 되살릴 때만 뜻이 있다(1절에서 하지 않기로 했다).

B가 기댈 디코더(지금 있는 것): Stored(필요 없음), DEFLATE(`flate-inflate`), Zstandard(Patch 명령, `zst.rs`가
이미 쓴다), LZMA(`lzma-decode` whole, LZMA-alone 헤더를 합성), BCJ/Delta(`bcj-*`). LZMA2, bzip2, Deflate64,
PPMd, RAR의 LZ/PPMd, AZO, LH는 모듈이 없다. solid 단위(7z folder, solid RAR, `.tar.gz`)는 푼 결과를 나눠 각
항목의 출력으로 삼는다(`Formula::split_patch`). 풀 때의 application bound(512 MiB)를 넘는 단위는 part
모듈로만 B가 되고 없으면 A다. 암호화된 항목은 복호화한 몸을 담는다.

정책 후보: P1 언제나 A, P2 디코더가 있으면 언제나 B, P3 레벨에 묶기(`inflated:max-level` = 3 미만이면 B,
이상이면 A), P4 몸마다 `probe`로 A가 문턱(예: 3%)을 넘게 이길 때만 A, P5 사용자 지정
(`--convert-streams=keep|recompress|auto`, 이름 미정).

**결정(미구현): P3을 기반으로 한다.** `-c`가 ZIP을 함께 묶을 때와 레벨의 뜻이 하나로 유지된다. 근거인 10gb
측정: 레벨 3에서 DEFLATE를 다시 만드는 쪽이 그대로 두는 쪽보다 109 MB(4.1%) 작았고 명령어는 37% 더 들었으며
풀기는 11.9 s에서 18.7 s였다(원본을 되살리는 비용을 잰 것이라 A가 B보다 얼마나 이기는지는 따로 재야 한다).
P4, P5는 P3이 놓치는 경우가 측정으로 보일 때 더한다. 디코더가 없는 몸은 레벨과 무관하게 A이고, 그런 대체는
`--stats`와 `-v`에 방식별 개수로 알린다.

**지금 코드는 A뿐이다**(convert.rs 모듈 문서: "policy A of the design: no body carried as it is"). B를 하려면
정책과 디코더 모듈이 필요하고, 모듈 추가(LZMA2, bzip2, ...)는 B가 실제로 필요하다는 것이 측정으로 보일 때만
한다 [남음].

## 4. 용례 2: 이미 있는 Aqueous 아카이브의 설정 바꾸기

재압축하지 않는다. 바꾸는 것은 블록 위의 층(미러 블록, 암호화의 봉투)뿐이고 아카이브 자체(segment, 덮어쓴
항목, tombstone, `segment-status`, journal 지점)는 그대로 둔다. **`--convert`는 `--compact`가 아니다**:
journal에 대한 지시(`--keep-since`, `--drop-history`, `--keep-until`)가 있을 때만 줄인다. 순서는 입력을
`append::open`처럼 잠그고 열기(암호화되었으면 복호화, 미러는 `mirror::check`, 손상은 4.4절), `rewrite_as`로
블록 복사(`History::Whole`; 바뀌는 것은 spacer, 미러, 크기 힌트, footer뿐), `Mirroring`/`Sealer`로 감싸기(`-c -P
-A`의 출력 층과 같은 순서, `crates/aqr-compress/src/output.rs`), 다시 열어 트리와 내용을 맞춰 보기다.

### 4.1 바꿀 수 있는 것

| 옵션 | 하는 일 |
|---|---|
| `-P` | 새 file key와 nonce로 봉하고 평문에 크기 힌트 블록을 넣는다. nonce를 다시 쓰지 않으므로 append의 문제가 없다 |
| `--no-passphrase` | 복호화해 쓰고 크기 힌트 블록을 뺀다 |
| `-A` / `--no-archival` | 미러 블록을 넣는다(암호화 출력이면 봉한 헤더의 미러도) / 뺀다 |
| `--keep-since`, `--drop-history` | `--compact`와 같다 |
| `--keep-until SPEC` | 고른 지점의 상태까지만 읽는다(`Layers::until`). 마지막 segment의 지점이면 바뀌는 것이 없다. 제자리에서는 `--rollback`이 다시 쓰지 않고 자른다 |

- 주지 않은 축은 **입력의 설정을 이어받는다**("주지 않으면 없음"이면 `aqr --convert -A x.aqr` 하나로 암호가
  조용히 벗겨진다). 벗기는 것은 `--no-passphrase`, `--no-archival`로만 한다. `-P`와 `--no-passphrase`, `-A`와
  `--no-archival`을 함께 주면 오류다. 암호만 이어받고 다른 축을 바꾸면 같은 암호로 새 file key와 nonce로
  다시 봉한다. 이미 그런 설정에 그 옵션을 주면 바뀌지 않은 축이고(`-P`는 새 암호로 바꾸는 것이니 바뀐 축),
  **아무 축도 바뀌지 않으면 아무 일도 하지 않는다**(오류 아님, 종료 0, `-o`가 있어도 쓰지 않는다. 손상된
  입력은 예외).
- 바꿀 수 없는 것: 레벨, `-S`, `-b`, `--lossy`, 재압축기의 선택(블록 내용을 바꾸니 재압축이다. 주면 오류).
  `.aqr`을 용례 1의 원본 형식으로 더하면 할 수 있다(정책은 늘 A). 원할 때만 한다 [남음].

### 4.2 출력 자리

`-o`가 없으면 제자리: 옆에 `ARCHIVE.PID.part`로 쓰고 검증한 뒤 rename한다(남는 것은 옛 아카이브거나 새
아카이브). `-o`가 있으면 새 파일이고 입력은 남긴다. 잠금은 `append::open`처럼 건다.

### 4.3 암호

필요한 암호는 많아야 둘이다: 이전(암호화된 입력을 열 암호)과 이후(`-P`의 새 암호). `-P` 없이 암호화된 입력을
다시 봉할 때는 이전 암호를 쓴다. 터미널에서는 이전을 먼저, 이후를 나중에 묻고(`Passphrase of x.aqr:`,
`New passphrase for x.aqr:`; 이후는 두 번) 터미널이 없으면 표준 입력에서 한 줄씩 이전 → 이후로 읽는다.
`--passphrase-from`은 둘이 필요하면 `;`로 나눠 `이전;이후`(`env:OLD;stdin`), 하나면 출처도 하나다. 수가 맞지
않으면 오류이고 `--convert`에서는 `-P`를 뜻하지 않는다. 그래서 `;`가 든 경로는 `fd:N`으로 넘겨야 하고, 이
규칙은 `-c`, `-d`에도 같다. 용례 1의 암호화된 ZIP, 7z도 같다(원본의 암호가 이전).

### 4.4 복구

`aqr`에 `--repair`는 없고 `--convert`가 고친 결과를 파일로 남긴다(`-d`, `-t`는 메모리에서 고쳐 읽는다:
`mirror::repair`). 손상된 입력은 1단계에서 고치고(암호화된 입력은 인증되지 않는 청크를 `decrypt_lossy`로 풀어
그 범위를 `erased`로 넘긴다) 나머지는 그대로 진행한다. 고치는 것은 바뀐 것으로 친다(`aqr --convert
damaged.aqr`이 고쳐 쓰고 무엇을 고쳤는지 알린다). 잃는 것 없이 고칠 수 있을 때만 쓰고, 블록을 되살리지 못해
파일을 잃게 되면 잃을 파일을 알리고 실패한다. 제자리에 쓰면 손상된 원본은 rename으로 사라지므로 남기려면
`-o`를 쓴다. 미러 블록이 없어도 footer를 다시 만드는 복구는 된다.

### 4.5 복호화한 평문

`rewrite_payload`가 온전한 암호화 입력의 데이터 블록을 4 MiB씩 복사하며 복호화하고 지나간 청크를 놓는다
(암호화된 입력의 `--history`도 읽는다). 손상된 입력만 전부 메모리에 푼다(`IN_MEMORY` 16 GiB 상한, 넘으면 실패:
복구도 `repair`가 메모리에서 하므로 같은 상한). 암호화된 입력의 `--at`, `--diff`는 아직 읽지 않는다 [남음].

### 4.6 SFX를 소스로 하지 않는 이유

SFX는 네이티브 blob이 있는 모듈을 shorthand 블록(해시 32바이트)으로 적는다. 독립된 `.aqr`로 떼려면 그
모듈의 전체 블록을 펼쳐야 하는데 `registered_module`(`aqr-decompress`)은 현재 `known.rs`의 모듈만 안다
(`released.rs`의 옛 모듈은 해시뿐). 제대로 하려면 레지스트리에 한 번이라도 들어간 모듈의 블록을 aqr이 전부
싣고 배포되어야 하고, 스펙상 레지스트리는 지워지지 않으니 릴리스마다 늘기만 한다. 변환 하나를 위해 바이너리를
키울 수 없다. 옛 SFX를 `-d`로도 열 수 없는 같은 문제는 레지스트리의 문제로 따로 정한다(옛 모듈을 내려받기,
해제는 SFX 자신에게 맡기기, 그대로 두기). SFX의 내용이 필요하면 SFX 자신으로 풀거나 `aqr -d`로 푼 다음 `-c`로
묶는다. 반대 방향(`.aqr` → SFX)은 `--format sfx`가 한다.

## 5. 남은 일

- 3.2절의 B(몸 그대로)와 정책 P3(P4, P5), 필요한 디코더 모듈.
- 3.1절: 7z, RAR, ALZ/EGG, tar의 spec "Converting from" 절, RAR와 Xceed의 주석.
- `--compact`가 암호화된 아카이브와 미러된 아카이브도 받게 하기. 지금은 `edit_args`(`args.rs`)가 `-P`, `-A`를
  거절하고 `append.rs`가 암호화된 것과 미러된 것을 거절한다. `--convert`와 같은 길(`rewrite_layered`)로 걷어
  낼 수 있다.
- 열린 문제: 복구에서 파일을 잃는 것을 받아들이는 옵션(이름, 잃은 파일을 `-d`의 `#salvaged`처럼 남길지),
