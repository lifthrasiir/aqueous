# 명령줄 도구의 남은 일

`aqr`의 명령줄에서 미뤄 둔 것들. 동작 자체는 `crates/aqr/src/main.rs`의 모듈 문서와 `aqr --help`가 정본이다.

## 표준 입출력

- **표준 입력의 순방향 풀기.** 지금 `aqr -d -`는 표준 입력을 임시 파일에 다 받은 다음에 푼다(`stdio::spool_in`).
  `ssh host 'aqr -c foo -o -' | aqr -d -`처럼 네트워크 너머로 쓰려면 받는 대로 시작해야 한다. 스펙은 세그먼트를
  앞에서부터 블록을 훑어 찾을 수 있게 하고("Interpreting a segment" 앞 문단) 세그먼트마다 모듈과 사전을 따로
  두므로, 세그먼트 하나씩 받아(기본 `-S` 256M, 스필에) 그 메타데이터 블록이 오면 풀고 버리는 순방향 리더가
  있으면 된다. 따져 볼 것:
  - 덧붙인 아카이브(`-a`/`-s`): 뒤 세그먼트가 앞의 항목을 바꾸거나 지운다. 순서대로 덮어쓰기/지우기로 적용하거나,
    footer의 상태를 모르니 거부한다.
  - `-A`의 복구(미러 블록)는 전체를 봐야 한다. 순방향으로는 손상을 알리고 실패만 한다.
  - 암호화된 아카이브는 청크가 앞에서부터 풀리므로 순방향과 맞는다.
  - 경로 선택(`-d - PATH`)은 메타데이터가 세그먼트 끝에 오므로 그 세그먼트의 leaf를 다 받아야 고를 수 있다.
- **압축 출력의 나머지.** 여러 파일의 아카이브는 만드는 대로 표준 출력에 쓴다. 단일 파일 아카이브(`Sink`가 쓴
  바이트를 다시 읽어 검증하고 실패하면 처음부터 다시 쓴다), 암호화(`Sealer`가 `Seek`을 요구한다), 다른 형식
  (`--format`)은 임시 파일에 다 만든 뒤 복사한다. 단일 파일은 입력 자체를 통째로 받아야 하므로 이득이 작지만,
  암호화와 tar 계열은 흘려보낼 수 있다.
- **다른 형식의 표준 입출력.** `aqr -d -`는 Aqueous 아카이브만 받는다(이름이 없어 형식을 모른다: 매직으로 고르면
  된다). `-o -`로 다른 형식의 단일 파일 스트림(`.gz` 등)을 풀어 내는 것도 아직 없다.

## 입력 고르기

- **와일드카드.** `-x`/`--exclude`와 `-d`/`-t`의 `PATH`에 패턴(`*`, `?`, `[...]`, `**`)을 받는 것. 지금은 이름이나
  경로를 그대로 맞춘다.
- **풀 때의 `-x`.** 지금 `-x`는 압축할 때만 받는다. 풀 때는 `extract::Selection`(Aqueous)과 `aqr_unpack::Select`
  (다른 형식)에 뺄 것을 더해야 한다.

## 그 밖

- `--json`은 `-t`만 받는다. `-I`(디버깅용)와 압축·풀기의 요약(지금은 `--ipc`의 메시지와 `--stats=FILE.json`)은
  필요해지면 더한다.

- 아카이브 안 항목의 삭제·이름 바꾸기: overlay archive와 함께(`docs/append-design.md`).
- 셸 자동 완성(`--setup-autocomplete`): fish와 PowerShell의 스크립트는 그 셸에서 돌려 보지 않았다(이 Mac에 없다).
  zsh는 zpty로, bash는 `_aqr`를 직접 불러 확인했다.
