# 프런트엔드 프로토콜 통합 (`--ipc` 하나로)

aqr를 다른 프로그램이 부리는 길은 `--ipc`, `--session`, `--serve` 세 개였다. 이것을 하나의 프로토콜로 합쳤고,
`-Z` 뒤에 숨기지 않고 문서로 남겼다. 규범 문서는 `man/aqripc.7`이고, 이 문서에는 그렇게 한 이유와 남은 일만 적는다.

## 1. 합치기 전

| | `--ipc` | `--session` | `--serve` |
|---|---|---|---|
| 하는 일 | 명령줄 하나의 작업을 진행 상황, 질문과 함께 실행 | 압축 대화상자가 떠 있는 동안 입력을 미리 훑고(`inventory`), `begin`으로 `--ipc`가 됨 | 아카이브 탐색(셸 확장, aqr-mount) |
| 메시지 | `event` 스트림, `ask`/`answer`, `control` | `control` + `id` | `id`를 단 요청과 응답, `more`, `data:N` 뒤에 바이트 |

문제는 넷이었다.

- 요청과 응답을 짝짓는 방식이 세 가지였다.
- 분할 응답과 바이너리 전송은 `--serve`에만 있었다.
- `data`라는 이름이 바이트 수와 항목의 압축 크기 두 가지 뜻으로 쓰였다.
- 오류는 문자열 하나였고, 암호 관련 오류만 따로 `encrypted`/`wrong` 필드를 썼다.

`--session`은 `--ipc`가 요청을 받지 못해서 생긴 서막일 뿐이었다.

## 2. 숨기지 않고 문서로 둔 이유

- **라이선스 경계:** aqr-mount는 GPL-3.0으로 따로 배포되고, aqr와는 이 프로토콜로만 이야기한다. 문서로 공개된
  인터페이스여야 "별개의 프로그램"이라는 경계가 분명하다.
- **쓰는 곳이 여럿이다:** aqr-win, aqr-mac, aqr-mount(Windows, Linux), 그리고 앞으로의 macOS 마운트다. 문서 없이
  코드끼리만 맞추면 세 벌로 갈라졌던 일이 되풀이된다.
- **`-Z`의 자리가 아니다:** `-Z`는 상수를 바꾸는 개발자 옵션이라, 프로그램 사이의 계약을 두기에 맞지 않다.
- **안정성:** 판 번호(hello)로 관리한다. 1.0 전까지는 판을 올려 호환되지 않게 바꿀 수 있다. aqr와 동봉 프런트엔드는
  늘 함께 배포되므로, 판 1(옛 세 옵션)은 남기지 않고 거절한다. `--serve`는 배포된 적이 없었다.

## 3. 설계에서 정한 것

- **바이트를 base64로 싸지 않는다:** 최상위 `"blob": N`만 예약하고, 그 뒤 N바이트를 그대로 흘린다. 본문의 어떤 필드와도
  부딪치지 않는다.
- **요청 하나에 응답 여럿:** `more`로 이어지고 마지막 응답만 `more`가 없다. 양쪽이 각자 번호를 매기는 요청을 보낸다.
  aqr의 질문도 그런 요청 하나이고, 작업의 사건은 `run`의 부분 응답이다. 그래서 틀이 하나로 끝난다.
- **`run`은 프로세스마다 한 번:** 스레드 풀, 신호, 중단(`crate::stop`)이 프로세스 전역이라서다. 실행 코드는 옛 `--ipc`
  그대로이고, `--session`의 `begin`처럼 main이 그 인자로 이어 간다. 탐색 요청은 그동안에도 처리된다.
- **`read`의 길이 제한을 없앴다:** 응답은 chunk(기본 1 MiB, hello로 4 MiB까지)씩 나뉘어 와서, 사이사이 다른 응답이 끼어든다.
  aqr-mount는 3 MiB 파일 하나를 요청 세 번에 읽던 것을 한 번에 읽는다. aqr-ipc의 `Served`는 4 MiB를 청한다.
- **텍스트가 아닌 경로:** `{"raw":HEX}`로 보낸다. Windows는 UTF-16 단위, Unix는 바이트 그대로다. 옛 판에서는 손실 변환되거나
  실패했다.
- **명령줄의 `--ipc`는 입력을 받지 않는다:** 명령줄의 다른 옵션(`-T`, `-Z`)은 그 프로세스가 처리하는 모든 것의 기본값이 된다.

## 4. 옛 것과 새 것

| 옛 판 | 판 2 |
|---|---|
| `aqr --ipc ARGS…` | `aqr --ipc` + `run {"args":ARGS}` |
| `aqr --session`, `inventory`, `begin` | `inventory`, `run` (같은 프로세스) |
| `aqr --serve` | `aqr --ipc` + `open`/`list`/`read`/… |
| `{"event":...}` | `run`의 부분 응답 |
| `{"ask":N}` / `{"answer":N}` | aqr의 요청 `ask` / 그 응답 |
| `{"control":"cancel"\|"finish"}` | `cancel {"of":N[,"finish":true]}` |
| `--serve`의 `{"id":N,...}` | `{"q":N,"op":...}` / `{"r":N,...}` |
| `"data":N` + 바이트 | `"blob":N` + 바이트 |
| `{"error":"..."}`, `encrypted`, `wrong` | `{"error":{"kind","message"}}` |
| `read`는 1 MiB까지 | `read`의 `len` 제한 없음, chunk씩 나뉜 응답 |

aqr의 테스트는 옛 판 모양으로 쓰여 있어서, `crates/aqr/tests/common/frontend.rs`가 메시지를 판 2로 옮겨 보내고 받는다.
그래서 테스트가 확인하는 동작은 그대로다.

## 5. 남은 일

- **`run` 여러 개:** 한 프로세스에서 작업을 동시에 돌려야 하면 풀과 중단을 작업별로 나눠야 한다. 지금은 `busy`로 막는다.
- **프런트엔드에서 aqr로 바이트 보내기:** 틀은 허용하지만 쓰는 요청이 아직 없다. 스트림을 받아 아카이브에 추가하는 것이 후보다.
- **신호로 끝날 때의 마지막 응답:** 신호로 프로세스가 끝나면 `run`의 마지막 응답(`exit`)이 오지 않는다. 프런트엔드는
  프로세스의 종료 상태로 안다.
- **aqr-mac:** macOS에서 빌드해 확인해야 한다(바꾼 것은 `job.rs`의 `Run` 사용뿐이다).
