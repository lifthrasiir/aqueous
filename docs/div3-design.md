# DIV3 (MS-MPEG4 v3)와 AVI의 무손실 재압축

AVI 안의 DivX 3 영상(`DIV3`)과 AC-3 음성을 파싱해 문맥 모델로 다시 부호화하는 계획.
`aqr-jpeg`와 같은 방식(허프만/VLC로 부호화된 계수를 산술 부호화로 바꾸고, 비트 단위로
같은 스트림을 재구성)이며, 아직 구현이 없다. 측정은 모두 추정이 아니라 아래 표의 실측만 적었다.

## 첫 표본

`mari.avi` (CD 이미지에서 꺼낸, 끝이 잘린 영화; 코퍼스 `F:\Data\aqr-corpus\aqr-div3`,
측정 전용): 640x352, 23.976 fps, Nandub 1.0rc2가 만든 것.

| 스트림 | 내용 | 크기 | 비중 |
|---|---|---|---|
| `00dc` | DIV3 (I/P 프레임, B 없음) | 468.8 MB, 103,584 청크 | 69% |
| `01wb` | AC-3 5.1, 384 kbps | 207.4 MB, 103,584 청크 | 31% |

`aqr -c`는 이 이미지를 100.0%로 저장한다 (포맷 처리가 없음). 컨테이너(JUNK, 청크 헤더)는
무시할 크기.

## 구성 요소

1. AVI 디먹서: `movi`의 청크를 스트림별로 나누고 나머지(헤더, `idx1`, JUNK, 순서)는 레코드로.
2. DIV3: 프레임 파싱, 계수/움직임 벡터를 문맥 모델로 재부호화, 동일 비트열 재구성.
3. AC-3: 공개 명세(ATSC A/52)로 구현할 수 있다. 비교 오라클은 ffmpeg.

## DIV3 테이블 확보 (결정: 2026-11-11)

MS-MPEG4 v3에는 공개 명세가 없고, VLC 테이블(DC, CBP, 계수 6벌, 움직임 벡터 2벌 등)이
구현에 필수다. 공개 구현은 LGPL이라 테이블을 복사할 수 없다 (PD 정책). 그래서
**설치된 ffmpeg 디코더를 블랙박스 오라클로 탐침**해 prefix 코드를 사실(데이터)로 역추출한다.
소스는 읽지 않는다.

탐침의 원리: 조작한 비트열을 담은 작은 AVI(`scripts/div3-probe/avi.py`)를 ffmpeg로 디코딩해
나온 픽셀(DC 평균, 단일 계수의 IDCT 패턴)에서 부호의 뜻을 읽는다. 16x16 I 프레임이
오라클로 디코딩됨은 확인했다. 확인한 I 프레임 머리는
`00` + qscale(5) + `10111` + rl_chroma(0/10/11) + rl(0/10/11) + dc_table(1)이다.

## 순서

1. 탐침: DC → CBP → 계수 표(intra/inter) → 움직임 벡터 → P 프레임의 MB 종류.
2. 파서 + 같은 비트열 재작성기(탐침한 표로), 실제 프레임 전부에서 왕복 확인.
3. 문맥 모델, 크기 측정 (목표: 영상 5% 이상).
4. AVI 디먹서와 공식(formula) 연결, AC-3.
